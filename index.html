TL;DR

Tree search breaks on the web. WebOperator makes it safe.

Tree search lets an agent compare alternatives and go back after a mistake. On real websites, going back is the hard part: some actions can't be undone (placing an order, deleting an item), and replaying earlier actions may not reproduce the same page (another shopper just bought the last chair).

WebOperator explores reversible actions first, checks every reconstructed page against a saved snapshot before continuing from it, and starts a fresh tree after a persistent change.

Abstract

A best-first search ranks candidate actions by both reward and reversibility, postponing ones that may permanently change the website. Validated backtracking rebuilds earlier pages from checkpoints and continues only when they match their snapshot. On WebArena it reaches 54.6% with gpt-4o, and the new WebReplayBench measures whether destructive actions are detected and never repeated.

Read the full abstract

LLM-based agents often operate in a greedy, step-by-step manner, selecting actions solely based on the current observation without considering long-term consequences or alternative paths. This lack of foresight is particularly problematic in web environments, which are only partially observable—limited to browser-visible content (e.g., DOM and UI elements)—where a single misstep often requires complex and brittle navigation to undo. Without an explicit backtracking mechanism, agents struggle to correct errors or systematically explore alternative paths. Tree-search methods provide a principled framework for such structured exploration, but applying them to the web introduces two challenges: replaying an action sequence may not reconstruct the same page, and some actions may irreversibly change the website. To address these challenges, we introduce WebOperator, a tree-search framework that enables validated backtracking and strategic exploration. Our method incorporates a best-first search strategy that ranks actions by both reward and reversibility, along with a robust backtracking mechanism that verifies reconstructed pages before continuing from them. It prioritizes reversible actions, postpones potentially irreversible ones, and discards earlier branches when its post-execution heuristic flags a possible persistent change. Experiments on WebArena and WebVoyager demonstrate the effectiveness of the framework. On WebArena, it achieves 54.6% task success with gpt-4o, outperforming all prior tree-search methods using the same backbone. Controlled ablations show that naive tree search can reduce performance, whereas action-aware selection and validated backtracking improve corrective search. We further introduce WebReplayBench, a web environment that records which actions actually change the website's state, to evaluate whether WebOperator detects irreversible actions and avoids repeating them during backtracking.

Why the web is different

Two obstacles to backtracking, and how WebOperator handles them

Standard tree search assumes the agent can always return to any earlier node. On a live website both halves of that assumption fail.

OBSTACLE 1 · IRREVERSIBLE ACTIONS

Some actions change the website for good

Submitting a form, deleting an item, changing a setting or logging out modify data that outlives the page. After such an action, earlier pages are no longer valid alternatives, and replaying a path that contains one repeats it.

Action-aware selectionBest-first search ranks actions by reward and reversibility: likely-destructive actions are deferred while reversible alternatives remain.
Re-rootingWhen a post-execution check flags a persistent change, earlier branches are discarded and a new tree starts from the resulting page.
OBSTACLE 2 · UNRELIABLE REPLAY

Going back may not reach the same page

Asynchronous updates, randomized content, sessions and other users change pages between visits. An agent can believe it is back on an earlier page while the action it planned there no longer makes sense.

CheckpointsReplays start from the nearest saved checkpoint instead of the root, cutting replay length from 7.47 to 1.81 actions per backtrack.
Speculative, snapshot-validated backtrackingAn earlier page is rebuilt in a parallel browser tab and checked against its saved snapshot. On a match the agent switches to that tab; on a mismatch the tab is closed and the original one is left unchanged.
Better candidates, too. A dynamic action space adapts the available actions to the current page, invalid actions are rejected before execution, and diverse candidates are generated with context variation and merged when redundant.

      WebReplayBench

      Ground truth for actions that change a website

      Task benchmarks such as WebArena check whether a task was completed, not which actions changed persistent state. WebReplayBench is a self-hosted shopping site with an inbox, to-do list, notes, orders and account settings, where every API response reports whether it changed the database.

      • 100 distinct actions: 50 that change the database and 50 that don't.
      • Includes the hard cases real sites have: writes through GET requests, links, menu items, radio buttons and autosaving fields, and requests that look destructive but write nothing.
      • Predefined action sequences build search-tree trajectories that reach each action, so detection and backtracking safety are measured without a language model.

      Try it

      Run WebOperator

      Give it a start URL and a task in the chat, or run the benchmarks from the paper. It works with OpenRouter, OpenAI and Azure OpenAI models.

      $ git clone https://github.com/kagnlp/WebOperator.git && cd WebOperator
$ pip install -r requirements.txt          # Python 3.12
$ playwright install chromium --with-deps
$ cp .env.example .env                     # add your API keys
$ python demo.py                           # opens a browser and waits for your task
      $ git clone https://github.com/kagnlp/WebOperator.git && cd WebOperator
$ cp .env.example .env                     # add your API keys
$ docker compose run --user $(id -u) weboperator --config weboperator/configs/demo.yml
      # host the WebArena sites first, then point WA_SHOPPING, WA_REDDIT, … at them (see README)
$ python run.py --config weboperator/configs/wa-gpt-4o.yml
$ python -m utils.move_exp --src_dir results/webarena/gpt-4o --dst_dir experiments/webarena/gpt-4o
$ python -m utils.eval_exp --results_dir experiments/webarena/gpt-4o --task_type webarena
      $ python run.py --config weboperator/configs/wv-gpt-4o.yml
$ python -m utils.move_exp --src_dir results/webvoyager/gpt-4o --dst_dir experiments/webvoyager/gpt-4o
$ python -m utils.eval_exp --results_dir experiments/webvoyager/gpt-4o --task_type webvoyager

      No admin rights for Playwright's system packages? Use the Docker tab. Benchmark commands assume the setup from the Demo tab; model, budget and agent options live in the YAML files under weboperator/configs/.
